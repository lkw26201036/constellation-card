# V1.4 七日星光旅程 Implementation Plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

Goal: Build a seven-day, interruption-safe local journey that gives users one small action per day and a shareable summary after day seven.

Architecture: Add a versioned journey data/service layer over the existing local action service, then expose it through a dedicated native WXML page and a compact home entry. Journey state is local-only; summary cards use the existing detail, poster and share infrastructure through a new journey/j1 card type.

Tech Stack: Native WeChat Mini Program JavaScript, WXML, WXSS; existing action-followup, reading-card, poster utility, local storage, and Node VM regression tests. No npm dependencies.

Spec: docs/superpowers/specs/2026-11-08-v1.4-seven-day-journey-design.md

## Global Constraints

- 每轮旅程固定生成 7 张卡，按顺序解锁。
- 用户可以中断旅程。中断不会清零、不会惩罚，也不会阻止用户继续使用普通卡片、牌阵、答案之书和骰子。
- 错过一天不会清零，也不会一次性解锁多张卡。
- 未绑定星座也可以开始，使用通用星光内容。
- 不新增账号、云端同步、强制广告、排行榜或连续签到惩罚。
- 旅程状态只保存在当前设备，核心流程离线可用。
- 只在用户主动开启本机体验记录后保存聚合事件，不记录行动内容、星座组合、身份或分享链接。

## Review Focus

- 用户在同一天完成延迟的前一天行动时，不应一次性完成两天；测试归 Task 1。
- 重复点击完成或重复进入总结页，不应重复增加完成数或生成重复历史；测试归 Task 1。
- 清理、损坏或旧版本旅程存储后，页面应回到可开始状态；测试归 Task 1。
- 未绑定星座和切换星座都不应改变旅程卡片内容；测试归 Task 1。
- 分享总结到另一设备时不应依赖本机旅程存储，也不应包含隐私字段；测试归 Task 3。

- The journey service exposes getJourneyView(date), startJourney(date), syncJourneyAction(action), getJourneySummary(startDate, completedDate), getJourneyCard(startDate, day, date), and getJourneyShareCard(query).
