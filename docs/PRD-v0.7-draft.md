# V0.7 下一版需求草案：星光牌阵与答案之书

状态：需求整理稿，尚未开始开发。已采纳原创牌组、七选三、保留单张主签与轻占卜氛围的方向。本次补充扩容和动画要求；60张为建议的扩容基线，具体交互参数在实现前细化。

## 1. 本次目标

在简约、高级的星座卡牌风格中，增加可参与的仪式感、轻娱乐和温柔陪伴。减少表单式选择，让用户通过选牌、揭晓、翻书主动参与。

不以“很准”“必定发生”作为吸引力；神秘感来自视觉、节奏和内容悬念。是否能吸引用户和促进分享，需要实际体验反馈验证。

## 3. 调研与产品选择

三张牌阵通常为每个位置分配不同的解释职责，例如过去/现在/未来、现状/阻碍/建议，而不是展示三张牌后只选其中一张。

参考：[Biddy Tarot — Easy Three-Card Tarot Spreads](https://biddytarot.com/blog/easy-three-card-tarot-spreads/)。只参考牌位结构，不使用其牌图或解读文案，也不采用其预测性主张。

采用原创“星光牌阵”，借鉴三张牌阵的交互结构和仪式感，表达“当下的你、可能的走向、给你的指引”。保留轻占卜氛围与象征解读，使用可能性和条件表达；不引入完整78张传统塔罗及正逆位体系，也不声称随机抽取可以客观预测未来。

## 5. 星光牌阵（建议方案）

### 5.1 用户流程

1. 进入牌阵页，看到一句引导：“留一个问题在心里，凭直觉选三张牌。”无需输入或提交问题。
2. 点击“展开牌阵”，牌堆归拢、轻洗牌，再展开为七张可选牌的弧形牌扇。
3. 用户依次选择三张不同牌，选中牌抬起并进入三个牌位，显示已选进度；尚未揭晓时可撤回重选。
4. 选满后点击“翻开星图”，依次揭晓三张牌，页面自然转入阅读状态。
5. 阅读三张牌、整体提示和一个可以马上尝试的小行动；可收藏整组、生成海报、分享整组或重新展开。

七张背面是本次可选牌，不表示总内容只有七张。小屏需保证牌张可区分、可点中，必要时改为错落两排，不能为了扇形外观牺牲操作。

### 5.2 三个牌位

| 牌位 | 表达职责 | 文案边界 |
| --- | --- | --- |
| 当下的你 | 一个可供自我观察的角度 | 用“也许、如果你正……”邀请对照，不断言用户隐藏的心理状态。 |
| 可能的走向 | 一个可探索的方向及其条件 | 说明选择与可能性的关系，不写必然预言，不制造危险、厄运或关系猜忌。 |
| 给你的指引 | 一个轻量、可执行的行动 | 不替用户作重大决定；用户保留选择权。 |

### 5.3 牌组与结果内容

建议将首批牌库从22张扩充至60张原创星光意象牌，例如月灯、潮汐、种子、归途。每张具有统一牌面结构、可辨识的独立插画或线描意象、名称、关键词及三个牌位对应的原创文本，共180段牌位文案。不能仅更换标题、颜色或几个词冒充不同牌。

内容编辑建议分六组各10张：探索与开始、情绪与休息、关系与边界、行动与成长、变化与选择、安定与生活微光。分类用于确保内容覆盖面，不新增用户必填步骤，也不代表吉凶或稀有度。

同一局抽取三张不同牌；每个牌位显示该牌对应的内容，而不是同一段万能解释复用三次。整组附简短的阅读引导和一个可执行的小行动，避免拼接出互相矛盾的建议。

七张候选牌在展开前从牌库中分配真实、互不重复的身份；用户选择决定哪张牌进入哪个位置，不能在点击时临时随机替换牌面。未揭晓的局内撤回重选不更换候选牌。

结果在首次揭晓前确定并保存，重放动画不重抽。重新开始才生成新组。通过本地规则组合，不要求联网AI解读，不上传用户心中问题。

避重规则建议：

- 同一局七张候选互不重复，最终三张互不重复。
- 新局候选排除最近四局已完成牌阵中出现的牌，最多12张；默认60张完整牌库仍有足够候选。
- 优先从较少遇见的牌中随机取样，逐步降低未见牌数量；不按固定顺序发牌。频次按已完成且唯一的牌阵记录，不因反复打开、重播动画或接收分享增加。
- 如果后续主题筛选使候选不足七张，先恢复距离上次出现最久的牌作为回退；保持单局不重复，不让页面抽取失败。避重为本机体验优化，不是对随机公正性或命运的主张。
- 避重范围是当前设备的可用本地记录；清理存储、换设备后无法继续之前的避重。不会改写已经生成、收藏或分享的牌阵。
- 答案之书仍保持同号同文，不套用牌阵避重；只有“替我选一个”可优先推荐近期未看的数字。

60张牌仍是有限内容库，重度使用最终会重复。目标是减少短时间内重复遇见的概率和相同文案的疲劳感，后续可按固定编号新增内容，保持旧牌和旧链接可读。

星座作为结果卡底部的个人视觉装饰；未选择时用十二星光。不能把用户的选择包装成计算出的命运或个人预测。

### 5.4 动画要求

- 动画为P0核心交付：牌堆归拢、弧形展开、选中移位、依次翻面、结果星图连接构成完整体验链；不能仅交付静态七张牌和简单淡入。
- 保持深松绿、暖白、低饱和金，配合少量纸面纹理与星图线条；神秘感通过留白、光线和节奏建立。
- 准备：牌堆轻微交叠与归拢，短暂洗牌后展成弧形，建议合计约1—1.5秒。
- 选择：抬起、描边亮起、轻投影，再平稳移入牌位，建议单次约250—400毫秒。
- 揭晓：分时翻面，辅以窄幅扫光，三张揭晓建议合计约1.5—2秒；随后正文淡入，避免强制长等待。
- 构图：选择时为弧形牌扇；选满后进入浅三角阵，中间略高、左右略低。逐张揭晓后出现细金线连接与短暂的星光汇聚，最后自然过渡到可阅读的结果区域。
- 翻面需处理背面隐藏、透视与层级，牌背不能镜像穿透；抬起和落位要有连贯的位移、缩放和阴影变化，避免突跳。
- 结果阅读时停下动画，不持续闪烁、旋转或漂浮。音效默认关闭，震动可选，不能依赖它们传递结果。
- “跳过动画”仅省去动效，不替用户选择牌、不改变既定结果；已有“减少动效”设置覆盖新流程。
- 防止连续点击造成重复选牌或重复保存；切后台、返回页面、重进结果时不能卡在翻牌中间。
- 先实现一套使用真实牌面素材的完整可交互动画样例，用微信真机查看节奏与手感，再铺满牌库；不能把静态效果图当作动画验收。

## 6. 答案之书

### 6.1 核心流程

1. 展示封面和引导：“把问题留在心里，选一个1—200的数字。”不强制填写问题。
2. 输入整数并确认，或点击“替我选一个”随机生成有效数字。数字入口保持简单，不展示200项长列表。
3. 书页轻启，页码先出现，答案与小行动逐步显现；动画建议约0.8—1.5秒，可跳过。
4. 用户可收藏、分享、生成海报、重新选数。

建议采用固定映射：同一个数字始终对应同一版本的一条答案，不因日期、星座、付费或广告而改变。同号可反复查看。更新内容必须引入新版本，旧分享保留原文。不是用同一个数字每次随机生成一句话。

### 6.2 200条内容的结构与编辑标准

- 必须完整提供编号1—200的200条原创答案，编号不遗漏、不重复；不是先放少量内容循环填充。
- 每条包括：编号、短标题、一句核心回应、可选的一段温柔解释、一个小行动。
- 建议核心回应约15—35字，解释约30—60字，小行动约10—30字；按真实阅读效果调整，不以凑字数验收。
- 编辑时可按自我接纳、休息恢复、关系边界、面对不确定、勇敢尝试、专注行动、耐心积累、生活微光八个方向各25条，共200条；分类只用于内容质量管理，不增加用户的选择步骤。
- 除字符串不同之外，还要检查语义差异；不能靠替换“月光/星光/微风”制造200条近似句。
- 不设吉凶、分数、稀有度与好坏等级；温柔但不保证成功，不声称问题必定迎刃而解。
- 少用空泛的“加油”“一切都会好”，多表达被理解的感受与可做到的小动作，避免命令、指责和强迫积极。
- 不复制出版物《答案之书》的原文或使用其封面素材；产品使用原创内容与视觉。

### 6.3 文案语气示例（用于讨论，编号和正文尚未定稿）

| 示例回应 | 小行动 |
| --- | --- |
| 你可以暂时没有答案，先照顾好正在寻找答案的自己。 | 放下手机两分钟，给自己倒一杯水。 |
| 走得慢一点，也是在认真走自己的路。 | 把今天最难的一件事，拆成一个小步骤。 |
| 不必把每一份期待，都变成自己的责任。 | 看看今天有没有一件事，可以温和地说“不”。 |
| 你不需要先变得完美，才值得被温柔对待。 | 记下一件今天已经做得足够好的小事。 |
| 有些清晰，需要在休息之后才慢慢出现。 | 暂停追问片刻，去窗边看看外面的光。 |
| 今天能做的一点点，也值得被认真收下。 | 完成一个五分钟的小任务，然后停下来认可它。 |

### 6.4 输入和使用细节

- 只接受1—200的整数；空白、0、201、负数、小数或非数字要就地温柔提示，不静默改成其他数。
- 提交后收起键盘，正文不被遮挡；内容过长时正常滚动，不裁切。
- 未选星座与断网状态均可使用核心内容。
- 同号再次查看不反复堆积历史。中断翻页后能打开原页，不随机换结果。

## 7. 收藏、分享与回访（建议）

- 牌阵收藏以整组三张保存，包含顺序、牌位和版本；不能只保存其中一张而丢失牌位含义。
- 答案收藏保存编号和版本；历史记录建议新增牌阵最近30组、书页最近30条，原有记录和收藏上限保持，新结果计入既有50项收藏容量。
- 接收者无需先抽取或看广告，即可看到朋友分享的完整结果；不得自动绑定对方星座。
- 牌阵海报展示三张牌、牌位和简短阅读提示；书页海报展示数字、回应和小行动。视觉沿用现有卡片体系，长内容可分屏阅读但导出不能裁切。
- 分享标题邀请参与，例如“我翻到了第127页，你会选哪个数字？”“三张星光，留给此刻的自己”；不声称神准，不强制转发解锁。
- 回访动力来自不同牌阵、200条书页和已收藏的陪伴内容，不靠新增强制每日次数限制。

## 10. 建议实施里程碑

**A：选牌体验升级。** 移除心情，新牌阵结构、原创牌背与牌面方向、选牌/揭晓动画、完整结果与旧数据兼容。先验证一个完整可交互样例的手感，再完成整套60张内容、美术和避重机制，提交可测试版本。样例仅用于阶段评审，不代表整套牌库已交付。

**B：答案之书与整体验收。** 完整200条原创内容、数字选择、翻页动效、收藏/历史/分享/海报以及首次访客适配；合并体验后真机验收并提交版本。

两阶段都属于下一版范围；第二阶段不能用示例内容代替完整200条交付。本次只产出需求稿，不执行这两个里程碑。
